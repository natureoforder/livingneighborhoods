# Living Neighborhoods edition — state of the nation and plan

## Goal

Turn the *Building Living Neighborhoods* collection (livingneighborhoods.org) into a clean, reader-structured Markdown edition in this repo, then bring it into the Alexander Wiki as reference material, a few pages first, then the whole. It feeds the wiki's "Build with Alexander" section.

Why: the original site is a maze of frames, inline JavaScript and source-folder navigation. Rufus used it a lot and still got lost in it; the material is valuable and the layout hides it. Re-routing it for readers is the main point, not just tidying the HTML.

## State of the nation (26 Nov)

**Archive.** The 21 Aug 2026 crawl is complete for everything linked from the live site: 209 HTML pages, 797 files, 207 MB (554 images, about 130 MB; 25 PDFs, about 65 MB, largest 17 MB). 524 linked URLs are dead on the live host; none have been looked up on the Wayback Machine. `scripts/verify.sh` fails in a fresh checkout because a global `*.jar` gitignore kept three files out of Git.

**The jar files.** Java applets (`gdraw…jar`) that ran the site's drawing pad (draw on a site plan in the browser) and the "unfolding movies", which replay a design step by step: St Mark's, Strood and a window design. Browsers dropped Java applets years ago, so these no longer run anywhere. They are kept as evidence; reviving the unfolding movies is a separate, later question.

**Conversion.** 48 of 209 pages converted, all raw Pandoc output: font and span soup, links to `.htm` files, table layout, legacy "Back to…" navigation. Nothing published.

**What the source holds.** `ht-0` (53 pages: introduction, main steps, Eishin, Fresno, West Dean, Mexicali), `actions` (33: steps of the generative code), `unfoldings` (27), `ht-1` (26: implementation, Mexicali, services), `noorefs` (16: Nature of Order cross-references), `library` (17 pages plus the 25 PDFs, including the *Generative Codes* book v10, the field guide, the Strood code and unfolding, the Mexicali process, the Schumacher lecture and *Battle*), `packets` (11: the six phases), `nbds` (4: Eishin, Samarkand, Strood Riverside, Texas), and small `ht-2`, `drawing-pad`, `extras`, `unfoldingmovies`, `worksheets`, `workpackets` folders.

## Decisions (Rufus, 26 Nov)

- **Order:** convert and clean first. `NEXT.md` is superseded by this plan and Beads; Wayback recovery and archive hardening become separate tasks.
- **All the work happens in this repo.** The wiki receives finished pages.
- **Structure for readers, not the old folders.** Laying out the material is real design work, done as its own step with a written layout doc.
- **In the wiki:** the edition is the wiki's `living-neighborhoods/` section; Works gets one entry page, `works/2006-building-living-neighborhoods`. (First tried under `works/living-neighborhoods/`; corrected 26 Nov, see `2026-11-26-edition-plan-explained.md`.)
- **Incremental on the wiki:** a pilot of a few pages first, Rufus checks it on the site, then the whole.
- **Permissions:** Rufus accepts the risk and goes ahead; others have recently had permission to put material up. A permission letter to Randy Schmidt and Maggie Moore Alexander is drafted later (a bead).
- **Beads** live in this repo (prefix `ln`); wiki bead `alex-88s.4` points here.

## Repo layout (this repo)

- `archive/` — unchanged: the immutable crawl, manifest and index.
- `raw/` — machine output: every archived page converted to Markdown, mirroring the source folders. Regenerated by script at any time; never hand-edited. Replaces the current `site/`.
- `edition/` — the clean edition in the reader structure, with images and PDFs at full size under `edition/assets/`. Built from the archived HTML (cleaner than going through `raw/`), then hand-edited; this is what goes to the wiki. Each page keeps `source`, `archive_path` and `source_sha256` frontmatter, so upstream changes can be flagged rather than overwritten.
- `scripts/` — archive, convert (`raw/`), build (`edition/`), check, and sync to the wiki. Scripts stay here.
- `verify.sh` checks `raw/` and `edition/` at least as strictly as it now checks `site/`.

## Order of work

1. **Housekeeping:** Beads; commit the jar files with a repo-level exception so verify passes; mark `NEXT.md` superseded.
2. **Raw:** convert all 209 pages into `raw/`.
3. **Layout:** read the material and write a layout doc: sections, page names, which source pages merge or split, the six-phase spine, where examples, theory, library and tools go, and exclusions (redirect stubs, click-agreement frames). Critiqued by a subagent before building.
4. **Edition:** build `edition/` from `raw/` per the layout: strip legacy navigation and markup, rewrite links to edition routes, turn image tables into figures with captions, one credit line per page. Checker script. Items needing human judgment are filed as Beads (not a Markdown queue, per Rufus's tasks-in-Beads rule).
5. **Wiki pilot:** the entry page, start-here, one phase with its steps, and Eishin, synced to `living-neighborhoods/` and published. Rufus checks it.
6. **Wiki full:** after Rufus's check, sync the whole edition and update the wiki's nav and Living Neighborhoods page.

Separate tracks, later: Wayback lookup of the 524 dead URLs (what they are, which matter, recover into `archive/recovered/`); independent URL inventory; reviving the unfolding movies; visual case studies; permission letter.

## How it feeds Build with Alexander

The wiki section runs room → house → hamlet. Living Neighborhoods is strongest at hamlet and neighbourhood scale and on process:

- **The generative code**: six phases (vision, diagnosis, modifying the code, density, public spaces, building volumes) and their steps, plus the *Generative Codes* book and field guide. The closest thing to a manual for a hamlet like Petit Bois Martin.
- **Hamlet-scale unfoldings**: main center, pedestrian centers, positive space, car positions, land tenure, zoning, surveying.
- **House scale**: house fronts, building shape, foundations and plinth, colour and light.
- **Process and money**: who designs, main contract and subcontract, construction organisation, community discussion; pairs with Book 3's process chapters.
- **Pattern Language starter sets** (room, house, hamlet, neighbourhood) are the other half: patterns say what to aim for, the code says in what order to decide it on site.
- **Examples, in priority order**: Eishin, Mexicali, West Dean, Fresno, Strood (a full worked code and unfolding), Samarkand, Texas.
