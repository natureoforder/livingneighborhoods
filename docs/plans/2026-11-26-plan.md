# Living Neighborhoods edition — state of the nation and plan

## Goal

A readable, searchable edition of *Building Living Neighborhoods* (livingneighborhoods.org) inside the Alexander Wiki as `living-neighborhoods/`, anchoring "Build with Alexander". This repo stays the preservation layer: archive, manifest, conversion scripts.

## State of the nation

**Archive (good, one snag).** The 21 Aug 2026 crawl is complete for everything linked from the live site: 209 HTML pages, 797 files, 207 MB (554 images, about 130 MB; 25 PDFs, about 65 MB, largest 17 MB). 524 linked URLs are dead on the live host; none recovered from the Wayback Machine yet. No independent URL inventory (search engines, Wayback CDX) yet, so unlinked pages may exist. Snag: `scripts/verify.sh` fails in this worktree because a global `*.jar` gitignore kept three Java drawing-tool files out of Git; they exist only in the original checkout. Fix: commit them with a repo-level `!*.jar` exception.

**Conversion (about a quarter, raw).** 48 of 209 pages are converted (about 50,000 words), mostly `actions/`, plus `packets/`, a few `ht-0/` pages and landing pages. The output is raw Pandoc: span and font soup from the old HTML, links still pointing at `.htm` files, table layout, legacy "Back to…" navigation, and the odd empty "TEXT coming" page. Readable in places, not yet an edition. Nothing has been published.

**What the source holds.** By folder: `ht-0` (53 pages: introduction, main steps, Eishin, Fresno, West Dean), `actions` (33: the generative-code steps), `unfoldings` (27: step-by-step unfoldings), `ht-1` (26: implementation, Mexicali, services), `noorefs` (16: Nature of Order cross-references), `library` (17 pages plus the 25 PDFs, including the *Generative Codes* book v10, the field guide, the Strood code and unfolding, the Mexicali process, the Schumacher lecture and *Battle*), `packets` (11: the phases), `nbds` (4: Eishin, Samarkand, Strood Riverside, Texas), and small `drawing-pad`, `extras`, `unfoldingmovies` folders.

**Wiki side.** `alexander-wiki/living-neighborhoods/` has three thin link pages (67 lines); its rebuild plan already says to replace them with this collection. Beads `alex-88s.3` (reuse terms) blocks `alex-88s.4` (integration).

## Where it lives (agreed 26 Nov), and the open details

- **Edition**: `alexander-wiki/living-neighborhoods/`, images and PDFs at full size under `living-neighborhoods/assets/` (adds about 200 MB to a 14 MB repo; plain Git is fine at this size, no file over 17 MB).
- **Routes (recommend)**: a reader-facing structure, not the source folders, keeping the source's broad Action and Theory split: `start-here`; `generative-code/` (one page per phase: vision, diagnosis, modifying the code, density, public spaces, building volumes, with its steps beneath; steps that don't belong to one phase go in a shared steps list); `unfoldings/`; `examples/` (Eishin, Mexicali, Fresno, West Dean, Strood, Samarkand, Texas); `theory/` (the `ht-0`/`ht-2` essays and the 16 `noorefs` Nature of Order cross-references); `library/` (essays and PDFs); `tools/` (drawing pad, worksheets, work packets; the Java applets no longer run, which the pages will say); `about` (credits, provenance, archive date, gaps, implementation and services pages from `ht-1`). Redirect stubs (three of the `packets` pages, the click-agreement frames) become listed exclusions. Every page keeps its `source:` URL, archive path and checksum in frontmatter.
- **Redirects**: the old wiki pages `collection` and `first-walk` redirect to the new entry page. Original `.htm` URLs aren't ours to redirect; the `source:` frontmatter and an About-page concordance from old URL to new page cover that.
- **Scripts (recommend: stay here)**. `convert_site.py` gets an output-directory option and writes the first full draft into the wiki checkout. After that the wiki owns the text and edits happen there. The archive is a frozen snapshot, so rerunning is rare; when needed, a checksum in frontmatter lets a script flag which pages changed upstream instead of overwriting hand edits.
- **This repo's `site/`** stops being a publish root. It is removed once the wiki holds the edition; `verify.sh` and `AGENTS.md` change to check the converter's output in the wiki checkout with at least the same strictness (page counts, frontmatter, links), not fewer checks.

**Wiki gate.** The wiki's rebuild plan holds volume work, Living Neighborhoods included, until you approve its vertical slice. Working on a local branch doesn't touch the live wiki, so I'd go ahead; merging waits for both the slice approval and permissions.

## How it feeds Build with Alexander

The wiki section is organised room → house → hamlet; Living Neighborhoods is mostly hamlet and neighbourhood scale and is strongest on process. What matters most:

- **The generative code itself**: the six phases and their steps (`packets/`, `actions/`), plus the *Generative Codes* book and field guide PDFs. This is the closest thing to a manual for a hamlet like Petit Bois Martin.
- **Hamlet-scale unfoldings**: main center, pedestrian centers, positive space, car positions, land tenure, zoning, surveying.
- **House-scale**: house fronts, building shape, foundations and plinth, colour and light.
- **Process and money**: who designs, main contract and subcontract, construction organisation, community discussion. These pair with Book 3's process chapters.
- **Pattern Language starter sets** (room, house, hamlet, neighbourhood, from the APL digest) are the other half: patterns say what to aim for, the generative code says in what order to decide it on site. Build with Alexander pairs each scale's pattern set with the matching code steps and unfoldings.
- **Examples, in priority order**: Eishin (the best documented, and the wiki already has a strong Eishin reading), Mexicali (self-built houses, the closest to a hamlet), West Dean and Fresno (shorter), then Strood (a full worked code and unfolding in the PDFs, which is unusual), Samarkand, Texas.

## Done-check for the build run

All machine-checked by a script in this repo, run against the wiki branch:

- Every one of the 209 archived pages maps to a wiki page or a listed exclusion with a reason; per-folder counts match `archive/PAGE-INDEX.csv`.
- Every page has `title`, `source`, `archive_path` and `source_sha256` frontmatter.
- Zero `<span`, `<font`, `.htm` links, "Back to …" lines or empty pages in the output.
- Link checker: zero broken internal links or images; images and PDFs at full size (byte-identical to the archive).
- Entry page, six-phase spine with previous/next, examples, theory, library, tools and About hubs exist; old `collection` and `first-walk` pages replaced.
- Review queue file listing pages needing human judgment (garbled tables, duplicate variants, thin pages).
- Local preview renders; `scripts/verify.sh` passes here.
- Beads set up here; this repo committed and pushed; the wiki branch committed and, under option A, not pushed.

Judging prose quality is not part of the check; that is what the review queue is for.
